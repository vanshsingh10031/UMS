\section{Document Overview}

\subsection{Purpose}
This document defines what the new UMS should provide to its three primary user
groups: administrators, employees/teachers, and students. It is intended to be
shared with academic and technical stakeholders to validate scope before
backend development begins.

\begin{scopebox}
\textbf{Important status note.} The modern UMS currently exists as an approved,
navigable frontend prototype using mock data. Features in this document are the
target product scope. Items visible in the prototype are experience baselines;
production authentication, permissions, business rules, APIs, and database
persistence remain to be implemented.
\end{scopebox}

\subsection{Sources used}
\begin{itemize}
  \item Approved Amrita-inspired UMS frontend prototype.
  \item Existing AUMS screenshots showing Academics, Evaluation, Exam Admin,
        Survey, Reports, Personal, Library, OPAC, Help, and Exam Application menus.
  \item Current academic ERP practices required for secure role-based operation.
\end{itemize}

\subsection{Role terminology}
\begin{itemize}
  \item \textbf{Admin:} authorized academic, examination, department, library,
        or system administrators. Exact rights depend on assigned permissions.
  \item \textbf{Employee/Teacher:} faculty members and eligible academic employees
        responsible for courses, attendance, evaluation, mentoring, and reporting.
  \item \textbf{Student:} enrolled learners using academic self-service features.
\end{itemize}

\section{Feature Principles}

\begin{itemize}
  \item \textbf{Role-based access:} every screen and action is controlled by backend permissions.
  \item \textbf{Single source of truth:} academic records are stored centrally with effective dates and history.
  \item \textbf{Approval where needed:} grade changes, attendance corrections, result publication,
        and sensitive master-data changes follow configurable approval workflows.
  \item \textbf{Auditability:} important actions record who acted, what changed, when, and why.
  \item \textbf{Operational clarity:} every page supports loading, empty, success, validation, and error states.
  \item \textbf{Responsive experience:} core workflows work on desktop, tablet, and mobile.
  \item \textbf{Controlled modernization:} useful AUMS functions are retained with clearer navigation,
        search, filtering, export, and accessible design.
\end{itemize}

example, an Exam Controller may publish results without being allowed to edit
student master data, while a Department Chair may approve grade changes only
for their department.

\section{Admin Features}

\subsection{Admin Dashboard}
\begin{itemize}
  \item Display total students, faculty, courses, departments, active batches, and current semester.
  \item Show attendance trends, pending approvals, mark-entry completion, upcoming examinations,
        timetable conflicts, notices, and recent administrative activity.
  \item Provide quick actions for adding users, creating course offerings, publishing announcements,
        scheduling examinations, and opening frequently used reports.
  \item Support campus, department, programme, academic year, semester, and date filters.
  \item Allow dashboard widgets to respect each administrator's permissions and scope.
\end{itemize}

\subsection{Identity, Roles, and Access}
\begin{itemize}
  \item Create, activate, suspend, unlock, and archive user accounts.
  \item Assign one or more roles, campus scopes, department scopes, and action permissions.
  \item Support institutional SSO or secure local authentication with password policies and MFA readiness.
  \item Configure session timeout, login controls, and account-recovery workflows.
  \item Review login history, failed attempts, active sessions, and permission changes.
  \item Impersonation, if permitted, must be restricted, visibly indicated, and fully audited.
\end{itemize}

\subsection{University and Academic Master Data}
\begin{itemize}
  \item Maintain campuses, schools, departments, programmes, regulations, academic years,
        semesters, sections, buildings, rooms, laboratories, and holidays.
  \item Maintain staff master records: employee ID, name, department, designation,
        employment status, contact information, and teaching eligibility.
  \item Maintain student master records: student ID, programme, batch, semester,
        section, academic status, mentor, and contact information.
  \item Maintain course and subject data: codes, titles, credits, type, prerequisites,
        syllabus version, owning department, and active status.
  \item Maintain batch capacity, class sections, programme duration, semester structure,
        and curriculum/stem-chart mappings.
  \item Prefer inactive or archived states over deleting historical academic records.
\end{itemize}

\subsection{Curriculum, Course Administration, and Registration}
\begin{itemize}
  \item Create and version programme curricula and stem charts.
  \item Define core, elective, laboratory, project, audit, and value-added course categories.
  \item Create semester course offerings with capacity, section, faculty, room, and delivery mode.
  \item Allocate primary and supporting faculty; view workload and allocation conflicts.
  \item Configure registration windows, add/drop periods, prerequisites, credit limits,
        arrear rules, and approval requirements.
  \item Register students individually or in bulk and track unregistered or partially registered students.
  \item Manage course withdrawal, transfer, repeat registration, and section changes with history.
  \item Produce registration status, course demand, capacity, and exception reports.
\end{itemize}

\subsection{Timetable and Academic Calendar}
\begin{itemize}
  \item Build weekly timetables by programme, batch, section, faculty, classroom, and laboratory.
  \item Detect faculty, room, batch, and time-slot conflicts before publication.
  \item Configure slot patterns, working days, breaks, holidays, substitutions, and special sessions.
  \item Publish role-specific timetable views for administrators, teachers, and students.
  \item Support view, print, download, and calendar export.
  \item Maintain the academic calendar for registration, instruction, assessment,
        examinations, holidays, result publication, and institutional events.
\end{itemize}

\subsection{Attendance Administration}
\begin{itemize}
  \item Define attendance rules, eligible course types, thresholds, session durations,
        grace periods, lock dates, and shortage categories.
  \item Monitor attendance capture completion by campus, department, course, faculty, and date.
  \item Review missing attendance, abnormal patterns, class cancellations, and late entries.
  \item Configure attendance-correction requests with reason, evidence, approval, and audit history.
  \item Produce daily, monthly, course-wise, student-wise, shortage, and eligibility reports.
  \item Notify teachers about pending attendance and students about shortage risk.
\end{itemize}

\subsection{Evaluation Configuration and Mark Governance}
\begin{itemize}
  \item Create evaluation components such as quizzes, assignments, laboratories,
        mid-semester examinations, end-semester examinations, projects, and viva.
  \item Define component weights, maximum marks, pass marks, absence rules,
        rounding rules, and contribution to the final grade.
  \item Create examinations and configure mark-entry windows and authorized evaluators.
  \item Configure class grade rules, grade boundaries, moderation rules, and grade-mark categories.
  \item Track mark-entry completion and identify missing, absent, withheld, or invalid entries.
  \item Assign grades, apply approved grace marks, and calculate final outcomes.
  \item Permit grade changes only through reasoned, permission-controlled workflows with old/new values.
  \item Lock finalized marks and grades; reopening requires authorized approval and an audit record.
  \item Generate class-grade, classwise student, attendance, registration-tracking,
        and grade-mark category reports.
\end{itemize}

\subsection{Examination Administration}
\begin{itemize}
  \item Create examination sessions, schedules, eligible courses, venues, and exam patterns.
  \item Allocate halls, seating, invigilators, and examination duties.
  \item Generate and publish examination timetables and hall tickets.
  \item Manage student exam applications, eligibility, fee status, and approval.
  \item Track mark/grade entry status across courses and departments.
  \item Produce student-wise arrear, course-wise arrear, number-of-arrears,
        and performance-analysis reports.
  \item Manage withheld, malpractice, absent, incomplete, revaluation, supplementary,
        and improvement-examination cases.
  \item Approve and publish results with version, publication time, and authorized sign-off.
\end{itemize}

\subsection{Survey and Feedback Administration}
\begin{itemize}
  \item Create course feedback, faculty feedback, institutional surveys, and custom questionnaires.
  \item Configure audience, anonymity, open/close dates, mandatory status, and reminders.
  \item Track participation without exposing anonymous response identities.
  \item Produce non-submitted-user reports and aggregated response analysis.
  \item Restrict detailed survey results to authorized users.
\end{itemize}

\subsection{Reports and Analytics}
\begin{itemize}
  \item Student reports: profile, enrolment, registration, attendance, performance,
        progression, arrears, and graduation eligibility.
  \item Staff reports: profile, course allocation, teaching load, timetable,
        attendance-entry completion, and mark-entry completion.
  \item Attendance reports: daily, course-wise, student-wise, shortage,
        exception, and correction history.
  \item Course-offering reports: capacity, enrolment, allocation, schedule,
        cancellations, and registration exceptions.
  \item Mark and grade reports: component marks, final marks, grade distribution,
        pass percentage, moderation, grace marks, changes, and publication status.
  \item Export authorized results to PDF, spreadsheet, or CSV with report metadata and filters.
  \item Provide trend dashboards without exposing personally identifiable data beyond user permission.
\end{itemize}

\subsection{Announcements, Notifications, and Events}
\begin{itemize}
  \item Create public, campus, department, programme, course, batch, or user-specific notices.
  \item Schedule publishing and expiry; support attachments, acknowledgement, and priority.
  \item Trigger notifications for registration, timetable changes, attendance shortage,
        assignments, examinations, mark entry, results, library dues, and approvals.
  \item Maintain delivery and read status for in-app messages; support future email/SMS/push integration.
\end{itemize}

\subsection{Library and OPAC Administration}
\begin{itemize}
  \item Maintain books, editions, authors, publishers, subjects, copies, locations, and digital resources.
  \item Manage issue, return, renewal, reservation, fine, lost/damaged, and exception workflows.
  \item Configure borrowing limits and loan periods by user category.
  \item Provide circulation, overdue, inventory, utilization, and fine reports.
  \item Connect the UMS library entry point to OPAC or an existing library platform where required.
\end{itemize}

\subsection{System Settings, Audit, and Operations}
\begin{itemize}
  \item Configure branding, academic defaults, numbering, date formats, document templates,
        notification templates, integrations, and feature flags.
  \item Review audit logs by user, module, action, record, date, and outcome.
  \item Monitor integration failures, background jobs, import/export jobs, and notification delivery.
  \item Support controlled data imports with validation, preview, error reports, and rollback planning.
  \item Define retention, archive, backup, restore, and disaster-recovery procedures.
\end{itemize}

\begin{itemize}

  \item Upload or update profile photo and edit permitted account fields.
  \item View account status and request correction of protected HR-managed information.
  \item Access My Profile, View Profile, Update Account, and password/session controls.
\end{itemize}

\subsection{Academics, Curriculum, and Timetable}
\begin{itemize}
  \item View programme stem charts, course syllabus, learning outcomes, credits, and prerequisites.
  \item View and print personal timetable, course timetable, room details, and academic calendar.
  \item Receive timetable-change, substitution, room-change, and cancellation notifications.
  \item View assigned workload and report allocation or scheduling issues.
\end{itemize}

\subsection{My Courses and Student Rosters}
\begin{itemize}
  \item View assigned course offerings, sections, co-faculty, enrolment, and course settings.
  \item View searchable student rosters with permitted academic details and registration status.
  \item Track course registration and identify students who have not completed registration.
  \item Access class communication, announcements, materials, attendance, evaluation, and reports.
  \item Export authorized class lists while protecting restricted student information.
\end{itemize}

\subsection{Attendance Capture}
\begin{itemize}
  \item Open the scheduled class session and mark students present, absent, late, or excused.
  \item Support bulk marking, individual correction before lock, and optional remarks.
  \item Show session date, time, room, enrolled students, and already-recorded status.
  \item Save drafts where permitted and clearly confirm final submission.
  \item Request corrections after lock with reason and supporting evidence.
  \item View class attendance history, shortage lists, student percentages, and pending sessions.
  \item Prevent attendance entry for unauthorized courses or invalid dates.
\end{itemize}

\subsection{Assignments and Study Materials}
\begin{itemize}
  \item Create assignments with title, instructions, attachments, marks, rubric,
        release date, deadline, late policy, and eligible students.
  \item Edit or cancel assignments before configured cut-offs and notify affected students.
  \item View submissions, non-submitters, late submissions, file history, and student remarks.
  \item Evaluate using marks or rubrics, add feedback, return work, and publish scores.
  \item Upload notes, presentations, references, links, laboratory manuals, and recordings.
  \item Organize materials by course, unit, topic, week, or resource type and control visibility.
\end{itemize}

\subsection{Evaluation, Marks, and Grades}
\begin{itemize}
  \item View evaluation components and examinations configured for assigned courses.
  \item Create components or exams only when the teacher's permission and academic rules allow it.
  \item Enter marks individually or in a validated grid; support authorized spreadsheet import.
  \item Record absent, withheld, malpractice, incomplete, or not-applicable status.
  \item Validate mark range, missing entries, duplicate students, and completion before submission.
  \item View mark-entry status and submit completed components for review or locking.
  \item Apply class grade rules and assign grades only when permitted.
  \item Request grade changes with old grade, proposed grade, reason, evidence, and approval trail.
  \item Apply grace marks only under authorized rules; teachers should not bypass policy.
  \item Access class-grade reports, classwise student reports, attendance reports,
        registration tracking, and grade-category details for assigned courses.
\end{itemize}

\subsection{Examination Responsibilities}
\begin{itemize}
  \item View examination timetable, venue, invigilation duties, evaluation allocation, and deadlines.
  \item Confirm or report conflicts in assigned examination duties.
  \item Access authorized mark-entry and grade-entry tasks.
  \item View course-wise arrear and performance reports where the employee's role permits.
  \item Submit examination-related requests and track their status.
\end{itemize}

\subsection{Reports, Survey, Search, Library, and Help}
\begin{itemize}
  \item Run authorized student, attendance, course-offering, mark, grade, and grace-mark reports.
  \item Participate in assigned surveys and view non-submission reports only when authorized.
  \item Search permitted students, courses, faculty, rooms, and academic records.
  \item Search OPAC, reserve resources, view loans, renew items, and review fines.
  \item Access contextual help, process guides, support requests, and system announcements.
\end{itemize}

\section{Shared End-to-End Workflows}

\subsection{Course Offering and Registration}
\begin{enumerate}
  \item Admin prepares curriculum, semester, course offering, capacity, faculty, and schedule.
  \item System validates prerequisites, clashes, credit limits, and programme eligibility.
  \item Student registers or Admin performs authorized bulk registration.
  \item Required approvals are routed to the designated academic authority.
  \item Confirmed registration becomes visible to the teacher and student's timetable.
  \item Every add/drop/withdrawal is effective-dated and retained in history.
\end{enumerate}

\subsection{Attendance}
\begin{enumerate}
  \item Published timetable creates eligible class sessions.
  \item Teacher records attendance for the assigned class and submits it.
  \item System updates student/course percentages and identifies shortage risk.
  \item Student can view the published record.
  \item Post-lock corrections require a request, approval, and audit entry.
\end{enumerate}

\subsection{Evaluation and Result Publication}
\begin{enumerate}
  \item Admin or authorized teacher configures components, exams, weights, and grade rules.
  \item Teacher enters and validates marks for assigned students.
  \item System tracks completion and flags missing or invalid entries.
  \item Authorized reviewers moderate, approve, apply policy-based grace marks, and lock records.
  \item Exam authority assigns/finalizes grades and publishes results.
  \item Student sees the published result; later changes create a new auditable version.
\end{enumerate}

\subsection{Assignment Submission}
\begin{enumerate}
  \item Teacher creates and releases an assignment to an eligible course group.
  \item Student submits work and receives a dated confirmation.
  \item Teacher evaluates, records marks and feedback, and publishes the outcome.
  \item Student reviews feedback; authorized resubmission retains previous submission history.
\end{enumerate}

\subsection{Survey}
\begin{enumerate}
  \item Admin creates a survey and defines audience, anonymity, and dates.
  \item System notifies eligible participants and sends reminders.
  \item Participants submit responses; duplicate submissions are prevented.
  \item Admin reviews participation and aggregated results according to privacy rules.
\end{enumerate}

\section{Non-Functional Requirements}

\subsection{Security and Privacy}
\begin{itemize}
  \item Backend-enforced authorization, secure sessions, HTTPS, explicit CORS,
        input validation, rate limiting, and secure secret management.
  \item Least-privilege data access; students access only their own records,
        teachers access assigned academic scopes, and admins access permitted domains.
  \item Protection of personal, academic, examination, and audit data in storage and transit.
  \item Configurable retention and access logs for sensitive reports and exports.
\end{itemize}

\subsection{Usability and Accessibility}
\begin{itemize}
  \item Responsive layouts, keyboard operation, visible focus, labelled controls,
        readable contrast, scalable text, and clear validation messages.
  \item Consistent design system across dashboards, tables, forms, filters, dialogs, and reports.
  \item Search, filters, sorting, pagination, bulk actions, and exports for high-volume pages.
\end{itemize}

\subsection{Performance and Reliability}
\begin{itemize}
  \item Paginated APIs, optimized database indexes, caching for stable reference data,
        and background processing for large exports and notifications.
  \item Idempotent submissions where duplicate academic operations would be harmful.
  \item Monitoring, structured logs, health checks, backup verification, and recovery procedures.
\end{itemize}

\section{Integration Scope}

\begin{itemize}
  \item Institutional identity/SSO and directory services.
  \item Existing library platform and OPAC.
  \item Email, SMS, and push notification providers.
  \item Payment gateway for exam or other approved academic fees.
  \item Learning Management System, digital content, or video platforms where approved.
  \item HR, admissions, finance, and alumni platforms through governed APIs or imports.
  \item Calendar feeds and document-verification services.
\end{itemize}

Integrations should use documented APIs, environment-specific credentials,
retry policies, monitoring, and reconciliation reports. Direct uncontrolled
database coupling should be avoided.

\section{Acceptance Baseline}

A feature should be considered ready only when:
\begin{itemize}
  \item user stories and permission rules are approved by the responsible university owner;
  \item frontend and backend builds pass, database migrations are reviewed, and automated tests pass;
  \item validation, loading, empty, success, failure, and retry behavior are complete;
  \item audit events exist for sensitive operations;
  \item responsive, keyboard, accessibility, and supported-browser behavior is verified;
  \item reports and notifications affected by the feature are updated;
  \item manual smoke tests and user-acceptance steps are documented; and
  \item no mock data, debug text, embedded secrets, or unauthorized data exposure remains.
\end{itemize}
