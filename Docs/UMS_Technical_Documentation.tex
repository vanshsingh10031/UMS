\section{Product Direction}

The University Management System will be a secure, role-based ERP for
administrators, faculty, and students. The approved React prototype defines the
visual design, navigation, dashboards, and principal workflows. Production
development will connect this experience to a .NET 8 Web API and Microsoft SQL
Server.

\textbf{Current prototype:} responsive frontend, mock login, role dashboards,
tables, forms, charts, timetable, attendance, assignments, library, results,
notifications, and analytics. Mock data and authentication will be replaced
during production development.

\section{Architecture}

\begin{itemize}
  \item React communicates only with versioned .NET API endpoints.
  \item Controllers validate requests and delegate rules to application services.
  \item Entity Framework Core manages SQL Server access and migrations.
  \item Backend authorization is the source of truth for every protected action.
  \item Audit logs record important identity, attendance, marks, and data changes.
\end{itemize}

\section{Security and Engineering Rules}

\begin{itemize}
  \item Enforce least-privilege permissions in the backend, not only in the UI.
  \item Use HTTPS and secure HttpOnly cookies; never commit credentials or secrets.
  \item Validate all requests and use transactions for multi-record operations.
  \item Preserve operational history and audit sensitive academic changes.
  \item Every screen must support loading, empty, success, validation, and error states.
  \item A feature is complete only after build, test, permission, and responsive checks pass.
\end{itemize}

\section{Delivery Roadmap}

\begin{enumerate}[leftmargin=1.5em,itemsep=3pt]
  \item \textbf{Foundation:} confirm requirements, data ownership, roles, permissions,
        authentication, audit logging, environments, and CI/CD.
  \item \textbf{Masters and scheduling:} implement staff, student, course, batch,
        subject, timetable, and academic calendar workflows.
  \item \textbf{Teaching and assessment:} implement attendance, assignments,
        materials, examinations, marks, results, and reports.
  \item \textbf{Operations and launch:} implement library and notifications, then
        complete security, accessibility, performance, backup, and pilot testing.
\end{enumerate}

\section{Immediate Next Steps}

\begin{itemize}
  \item Freeze the first-phase functional scope with university stakeholders.
  \item Define the SQL Server schema and role-permission matrix.
  \item Implement secure authentication and typed frontend API services.
  \item Build the first complete workflow: Student Master from UI to database.
  \item Pilot with selected administrators, faculty, and students.
\end{itemize}
